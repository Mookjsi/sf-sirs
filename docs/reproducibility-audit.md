## Numerical discrepancy

The saved Phase 29 result gives M1 full-period RMSE `618.444501178261`, which rounds to `618.44` at two decimals; Table 3.1 prints `618.45`. Annual Fourier gives `691.045105092188`, which rounds to `691.05`; Table 3.1 prints `691.04`. Both differ by `0.01` at displayed precision. The rerun described in the existing reproduction guide matched the saved CSV. `verify_report.py` deliberately marks these two claims `FAIL` with a 0.005 tolerance. No report value or model result was changed.

The original H1 `h1_equal_season_summary.csv` uses only *identified* events as each season's denominator and therefore prints `0.8889` raw and `0.8519` blend. The report uses all parent timing events, including unresolved and mixed events, yielding `0.7083` and `0.7050`. The direct verifier computes the report's stated denominator from parent rows. The original summary CSV must not be cited as the report's equal-season fraction.

## Remaining gaps

The public repository still lacks redistribution clearance for the frozen M2 evaluation, H1 grid, observations, Park posterior summaries, and JIHS releases. The direct H1–H3 path needs the M2 evaluation and H1 design files and bypasses exploratory fit checkpoints. Chapter 4 reconstruction and timing now need only the M2 evaluation and compact Park weekly posterior summary; original Park MCMC remains optional. Phase 29 retains its historical input chain. Park MCMC and full M2 refitting were not run and are outside the fast verification path. The public repository alone therefore does not satisfy complete self-contained Level 2 reproduction.
